## 답변 원칙 (답변 채팅에만 적용)
- 모든 응답은 **개조식 + 명사형 종결**로 작성합니다.
- 조사·서술어를 최소화하고 핵심 명사구로 끊습니다.
  - 예: "SPEC을 구성했습니다" → "SPEC 구성 완료"
  - 예: "테스트를 실행했으나 3건이 실패했습니다" → "테스트 실행 / 3건 실패"
- 직관적으로 표현하기 위해, 표 형식을 적극적으로 사용합니다. 
- 단, 오류 원인 설명·트레이드오프 논의 등 맥락이 필요한 부분은 서술식 허용.

## 유의사항
- 모르는 부분은 솔직하게 모른다고 인정한다. 
- 모호한 부분은 반드시 사용자의 확인을 거친다.
- 틀릴 용기를 가져라. 대신 틀릴 수 있다는 것에 대해 사용자에게 명시하라.
- 좋은 의심은 프로젝트의 방향을 올바른 방향으로 이끈다. 끊임없이 의심하라.
- 작업이 끝나고 사용자에게 결과물을 대화로 전달할 때는 핵심 내용만 짧게 전달해라. 
  - 표와 불릿포인트, 이모티콘을 사용하여 직관적으로 표현할 것 
- PRD.md 나 Architecture.md 등 기획안에는 교육용 멘트를 넣지 않는다. 
  - 교육용 멘트는 Readme 에 넣을 예정
  - 기획안은 실무처럼 작업할 수 있도록, 실무와 연관된 내용만 기재

## 문서 이모지 규칙 (md 파일에만 적용 / 답변 채팅은 제외)
- md 문서에는 **정보를 전달하는 기호만** 사용한다. 장식 목적 이모지는 넣지 않는다.

### 허용 기호

| 용도 | 기호 |
| --- | --- |
| 판정 (O/X) | ✅ ❌ |
| 체크박스 | ☐ ☑ ⬜ ⬛ |
| 심각도·상태 등급 | 🔴 🟠 🟡 🟢 🔵 ⚪ 🔶 🔷 |
| 신규 항목 표시 | 🆕 |
| 난이도 | ⭐ ★ ☆ |
| 증감·방향 | → ← ↑ ↓ ⬆ ⬇ ▲ ▼ ± − ≥ ≤ |
| 번호 | ① ② ③ · ⓐ ⓑ ⓒ |
| 트리 다이어그램 | ─ │ ├ └ |
| 경고 ⚠️ · 잠금 🔒 · 팁 💡 등 | ❌ 제거 — **볼드**로 강조 |

### 금지 · 변환

| 대상 | 처리 |
| --- | --- |
| 섹션 헤더 · 표 라벨 · 불릿 선두 장식 이모지 | ❌ 제거 |
| 텍스트와 의미가 중복되는 이모지 (예 : `색상` 컬럼 옆 색상 원) | ❌ 제거 |
| 금지 마커 🚫 ⛔ | ❌ 로 통일 |
| 키캡 숫자 1️⃣ 2️⃣ | 일반 숫자 `1.` `2.` (표 셀에서는 `1`) |

- 판단 기준 : **기호를 지웠을 때 정보가 사라지면 유지, 인상만 사라지면 제거.**
