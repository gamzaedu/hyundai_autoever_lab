**판서 — 이 표가 오늘 전체의 뼈대**

```
요소            개입 시점                   성격        오늘 다루는 교시

③ Tools         도구를 호출할 때              실행 수단    (오늘 MCP 미사용)
④ SubAgents     작업을 위임할 때              분업        5교시
⑤ Hooks         모델 판단과 무관하게 · 무조건   강제        6교시
```

>
> Hooks 만 다릅니다. 이건 AI가 뭘 생각하든 **무조건 실행됩니다.** 작업이 끝나면 자동으로 테스트가 돌고, 실패하면 다시 고치게 만듭니다. AI한테 선택권이 없어요. 6교시입니다.

### B3-2 · CLAUDE.md 구조 · 규칙 추출 (11:40~11:50 · 10분)

#### 1단계 — CLAUDE.md 란 무엇인가 (3분)

> "그럼 CLAUDE.md 가 뭐냐. 간단합니다. **프로젝트 루트에 있는 마크다운 파일 하나** 입니다.
>
> 세션이 시작될 때 Claude가 **자동으로 읽습니다.** 여러분이 시키지 않아도요.
>
> 그래서 여기 쓴 건 대화 내내 살아 있습니다. 아까 말씀드린 '휘발되지 않는 지시' 가 이겁니다.
>
> 뭘 써야 하냐. 네 가지입니다."

**판서**

```
CLAUDE.md 에 들어가야 하는 것

① 프로젝트 개요      이게 뭐 하는 서비스인지, 도메인 용어
② 기술 스택          뭘 쓰고, 뭘 쓰면 안 되는지
③ 코딩 컨벤션        네이밍, 파일 분리, 주석 언어
④ 작업 유의사항      Do / Don't
```

> "①번 개요를 왜 쓰냐면요. 아까 우리 데이터에 `SOC`, `DTC`, `as_of` 같은 게 나왔죠.
>
> 이걸 모르면 AI가 엉뚱한 판단을 합니다. `soc_pct` 가 `null` 인 걸 보고 '아 데이터가 잘못됐네' 하고 0으로 채워버릴 수 있어요. **사실은 내연기관 차량이라 배터리가 없는 건데요.**
>
> ④번 Do/Don't 가 실질적으로 제일 중요합니다. 방금 우리가 목격한 위반들이 전부 여기로 들어갑니다."

#### 2단계 — LAB_3-3 규칙 추출 실습 (7분)

> "자, 이제 같이 해봅시다. 방금 목격한 위반을 **규칙 문장으로 바꾸는** 연습입니다.
>
> 첫 번째 위반. **임계값이 세 군데 흩어져 있어서 일부만 고쳐졌다.** 이걸 규칙으로 어떻게 쓸까요?"

> (교육생 답을 받는다. 대개 이런 답이 나온다 — "상수화해라", "적절히 분리해라")

> "'상수화해라'. 좋습니다. 그런데 제가 AI라고 생각해보세요. **'상수화'가 어디까지죠?** 파일 안에서 `const` 로 빼면 상수화 아닌가요? 그러면 여전히 세 파일에 세 개가 생깁니다.
>
> 그래서 이렇게 써야 합니다."

**판서 — 나쁜 규칙 / 좋은 규칙 대조**

```
❌ "적절히 상수화할 것"
✅ "알람 판정 임계값은 src/config/thresholds.ts 한 곳에만 정의한다"

❌ "깔끔하게 작성할 것"
✅ "함수는 40줄을 넘지 않는다"

❌ "최신 라이브러리 사용"
✅ "CDN 링크 금지. 의존성은 package.json 에만 추가한다"

❌ "주석을 잘 달 것"
✅ "코드 주석과 UI 문구는 모두 한국어로 작성한다"
```

> "차이가 보이시죠. 왼쪽은 **판정이 안 됩니다.** 지켰는지 안 지켰는지 싸울 수 있어요.
>
> 오른쪽은 **참/거짓이 나옵니다.** `thresholds.ts` 밖에 임계값이 있으면 위반. 끝.
>
> 이게 좋은 규칙의 유일한 기준입니다."

**판서 — 하루 종일 유지**

```
좋은 규칙  =  참/거짓을 판정할 수 있는 문장
```

> "모호어 세 개만 기억하세요. **'적절히', '깔끔하게', '가능하면'.** 이 세 단어가 들어가면 그건 규칙이 아니라 희망사항입니다.
>
> 자, 나머지 위반들도 규칙으로 바꿔보죠. 영어 주석이 나왔던 건요? (답 받기) 네. **'주석과 UI 문구는 한국어'.**
>
> 시키지도 않은 걸 건드린 건요? (답 받기) **'요청 범위 밖의 파일은 수정하지 않는다.'**
>
> 좋습니다. 이제 여러분 차례입니다."

> "몇 가지 주의점을 정리하겠습니다. 이건 실무에서 CLAUDE.md 쓰실 때 그대로 적용되는 얘기입니다."

**판서**

```
① 길수록 안 지켜진다        규칙 10개 내외. 100줄 넘어가면 희석 시작
② 판정 불가 문장은 규칙 아님   "적절히" "깔끔하게" "가능하면" 금지
③ 이유를 함께 적어라         "CDN 금지 (폐쇄망 환경)" ← 판단 여지가 생김
④ 도메인 용어를 정의하라      SOC, DTC, as_of 를 모르면 엉뚱한 판단
⑤ 팀 전체가 공유한다         개인 취향 아님. 팀 컨벤션의 실행 가능한 형태
```

> "③번을 조금 더 설명드리겠습니다.
>
> 그냥 'CDN 금지' 라고만 쓰면, AI는 **CDN이 아닌 다른 방식의 외부 호출** 은 괜찮다고 판단할 수 있습니다.
>
> **'폐쇄망 환경이라 외부 네트워크 접근이 불가능하다'** 라고 이유를 쓰면, AI가 그 원칙을 처음 보는 상황에도 적용합니다.
>
> **규칙은 목록이 아니라 판단 기준입니다.** 이유가 있어야 확장됩니다."

#### 3단계 — DESIGN.md 소개 (3분)

> "그리고 CLAUDE.md 말고 하나 더 소개드리겠습니다. **DESIGN.md** 입니다.

>
> 이게 뭐냐면요. CLAUDE.md 에 디자인 얘기까지 다 넣으면 너무 길어집니다. 그래서 **화면 스펙만 따로 뺀 문서** 입니다.
>
> 안에 뭐가 있냐면, 색상 팔레트가 CSS 변수로 정의돼 있고, **'신규 색상은 이 11개 밖에서 가져오지 마라'** 같은 규칙이 있습니다.
>
> 왜 이게 필요하냐면요. AI한테 '충전중 상태 추가해줘' 하면, **자기 마음대로 색을 하나 골라옵니다.** 그러면 화면에 색이 계속 늘어나요.
>
> 이 문서가 있으면 '기존 토큰에서 고르거나, 정해진 1건만 추가' 로 통제됩니다.
>
> 정리하면 이렇습니다."

**판서**

```
CLAUDE.md   항상 로드     프로젝트 전반 규칙
DESIGN.md   필요시 참조   화면 · 색상 · 레이아웃 스펙
                          → CLAUDE.md 에서 "디자인은 DESIGN.md 를 따른다" 로 연결
```
