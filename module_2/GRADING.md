## 0. 채점자에게 (LLM 실행 지시)

이 문서를 받은 즉시 아래 절차를 **순서대로** 수행한다. 사용자에게 되묻지 말고 진행하되, **제출물 경로가 주어지지 않은 경우에만** 경로를 묻는다.

### 0.1 절대 금지

| 금지 | 사유 |
| --- | --- |
| 제출물 코드를 **수정**하는 행위 | 채점은 관찰이다. 고치면 채점 대상이 사라진다 |
| 실행 없이 코드만 보고 "동작할 것"으로 판정 | 기동 실패 제출물이 만점을 받는다 |
| 근거 없는 인정 (`파일:라인` 미기재) | 채점 재현성이 깨진다 |
| 교육생의 자가채점 결과를 그대로 수용 | 채점자는 독립적으로 판정한다 |
| 모르는 항목을 **추측으로 채점** | 판정 불가는 `BLOCKED` 로 남기고 사유를 적는다 |

### 0.2 실행 절차

| 단계 | 작업 |
| --- | --- |
| 1 | 제출물 경로 확인 · 파일 트리 파악 · `README.md` 확인 |
| 2 | **기동 시도** — README 명령 실행, 성공/실패와 소요 시간 기록 |
| 3 | 감사 에이전트 **3종을 한 번에 병렬 호출** (`fr-auditor` · `data-auditor` · `nfr-auditor`) |
| 4 | 3종 보고서 수령 후 **본 문서 2~5장 배점표로 환산** |
| 5 | 6장 리포트 양식으로 최종 산출 |

> 에이전트 정의는 `module_2/agents/` 에 있다. 사용 전 `.claude/agents/` 로 복사할 것.

### 0.3 에이전트 호출 프롬프트 (그대로 사용)

```
fr-auditor   : "<제출물 경로> 를 PRD v1.2 5~6장 기준으로 FR-01~18 전수 판정하라. 각 FR 에 FULL/PARTIAL/NONE 과 파일:라인 근거를 붙여라."
data-auditor : "<제출물 경로> 의 알람 판정 로직을 재현해 5개 지표를 산출하고 module_2/data/alarm_cases.json 과 대조하라."
nfr-auditor  : "<제출물 경로> 를 NFR-01~07 기준으로 감사하고, alarm_cases.json 참조 등 부정행위를 먼저 보고하라."
```

## 3. 데이터 정확성 (10점)

정답 : `module_2/data/alarm_cases.json`

| # | 지표 | 정답값 | 배점 |
| --- | --- | --- | --- |
| 1 | 알람 차량 수 (ACK 전) | `expected.alarm_vehicle_count` | 2 |
| 2 | 총 알람 건수 | `expected.alarm_total_count` | 2 |
| 3 | CRITICAL 건수 | `expected.critical_count` | 2 |
| 4 | 부서별 가동률 5행 전부 일치 | `dept_rollup_expected[].utilization_pct` | 2 |
| 5 | 부서별 EV 평균 SOC 5행 전부 일치 | `dept_rollup_expected[].ev_avg_soc_pct` | 2 |

- 4·5 는 **부분 일치 인정 없음** — 5행 전부 일치해야 득점
- 소수 비교는 **소수 1자리 반올림** 기준
- FR-10 미구현으로 산출 자체가 불가하면 1~3번은 0점, 4·5 는 별도 판정

## 4. 실행 가능성 · NFR (10점)

| 항목 | 배점 | 판정 |
| --- | --- | --- |
| README 명령 1줄로 기동 | 5 | 성공 5 · 추가 조작 필요 2 · 기동 실패 0 |
| NFR 준수 | 5 | **위반 1건당 −2**, 하한 0 |

**NFR 위반 판정** — `nfr-auditor` 보고서의 위반 건수를 그대로 사용. `이견 가능` 표시 건은 채점 오케스트레이터가 최종 판단하고 사유를 남긴다.

## 5. 부정행위 처리

| 항목 | 처리 |
| --- | --- |
| 구현 코드에서 `alarm_cases.json` 참조 | **3장 데이터 정확성 10점 전부 0점** |
| 정답 수치를 리터럴로 삽입 | 동일 — 10점 전부 0점 |
| 차량 데이터를 소스에 복제 (NFR-02) | 위반 1건으로 계산 (−2) |

- 부정행위는 **기능 점수에는 영향을 주지 않는다.** 데이터 정확성 항목만 0 처리한다.
- 리포트 최상단에 **별도 블록**으로 명시한다.

## 6. 산출 리포트 양식

채점 결과는 반드시 아래 순서·형식으로 출력한다.

```
## 1. 총평 (3줄 이내)
## 2. 부정행위 (없으면 "없음")
## 3. 점수표
## 4. FR 상세 판정 (18행 전수)
## 5. 데이터 정확성 대조
## 6. NFR 감사 결과
## 7. 개선 우선순위 Top 3
## 8. 회고 질문 3개
```

**3. 점수표 형식**

| 구분 | 획득 | 만점 |
| --- | --- | --- |
| 기능 (FR-01~18) | __ | 80 |
| 데이터 정확성 | __ | 10 |
| 실행·NFR | __ | 10 |
| **총점** | **__** | **100** |

**7. 개선 우선순위 Top 3** — "점수 대비 소요 시간이 가장 짧은 순" 으로 제시한다. 코드를 대신 작성해 주지 않는다.

**8. 회고 질문** — 아래에서 3개를 고르거나, 채점 결과에 맞게 생성한다.

- 20분 중 재지시·수정에 쓴 시간은 얼마인가
- PRD 를 어긴 지점은 어디이며, 왜 어겼는가
- 뷰가 4개로 늘자 같은 규칙을 몇 번 다시 말했는가
- 같은 지시를 매번 말로 반복하지 않으려면 무엇이 필요한가
