| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v1.2 |
| 작성 조직 | 커넥티드카개발팀 |
| 대상 시스템 | 사내 업무차량 통합 관제 웹 콘솔 |
| 개발 기간 | **20분** (타임어택) |
| v1.1 대비 변경 | 실사용 필수 기능 4종 추가 · FR ID 전면 재정렬(FR-01~18) · **배점·채점 기준은 본 문서에서 분리** |

## 1. 배경 및 목적

사내 업무차량 30대가 각기 다른 담당부서에 흩어져 운영 중이며, 현재는 차량 상태를 부서별 엑셀로 관리하고 있음. 배터리 방전·통신 두절·정비 누락이 사후에야 발견되어 운행 차질이 반복되고 있음.

v1.0 파일럿 결과 다음 세 가지가 확인됨.

- 차량 단위 조회만으로는 **부서 단위 자산 운영 판단이 불가**
- 발견한 알람을 **조치로 연결하는 수단이 없음**
- 부서 담당자가 **자기 부서 차량만 보는 수단이 없어** 실사용을 포기함

본 콘솔 v1.2 는 다음을 목적으로 함.

1. 전 차량의 상태를 한 화면에서 확인하고, 조치가 필요한 차량을 즉시 식별
2. 부서 단위 운영 지표(가동률·평균 SOC·알람)로 자산 배분 판단 지원
3. 알람을 **확인 → 정비 입고 계획**으로 연결하는 최소 조치 워크플로 제공
4. 조회 결과를 **보고 산출물(CSV)** 로 반출

## 4. 데이터 명세

### 4.1 제공 파일 (`module_2/data/`)

| 파일 | 내용 |
| --- | --- |
| `vehicles.json` | 차량 30대 스냅샷 + 기준시각 `as_of` |
| `trips.json` | 차량별 최근 주행 이력 5건 |
| `alarm_cases.json` | ❌ **자가채점 전용 정답지** — 구현 코드에서 참조 시 데이터 정확성 0점 |

### 4.2 차량 필드

| 필드 | 타입 | 비고 |
| --- | --- | --- |
| `vehicle_id` | string | `VH-0001` 형식 |
| `plate` | string | 차량번호 |
| `model` / `powertrain` | string | `EV` / `HEV` / `ICE` |
| `status` | enum | `DRIVING` · `IDLE` · `MAINTENANCE` · `OFFLINE` — **`last_seen` 시점에 마지막으로 수신된 상태값** (현재 상태 아님) |
| `soc_pct` | number \| **null** | `ICE` 차량은 `null` |
| `fuel_pct` | number \| null | `EV` 차량은 `null` |
| `odometer_km` | number | 누적 주행거리 |
| `last_seen` | ISO8601 | 최근 통신 시각 |
| `location` | object | `name` · `lat` · `lng` |
| `owner_dept` | string | 담당 부서 |
| `dtc_codes` | string[] | 진단 코드, 없으면 `[]` |

> **현재 시각은 시스템 시각이 아니라 `vehicles.json` 의 `as_of` 값을 사용할 것.** (재현 가능한 운영·검증을 위함)

### 4.3 주행 이력 필드 (`trips.json`)

| 필드 | 타입 | 비고 |
| --- | --- | --- |
| `started_at` / `ended_at` | ISO8601 | 최근순 정렬 상태로 제공 |
| `distance_km` / `avg_speed_kph` | number | 주행거리 · 평균속도 |
| `energy_kwh` | number? | `EV` · `HEV` 만 존재 |
| `fuel_l` | number? | `ICE` · `HEV` 만 존재 |

> 파워트레인에 따라 존재하는 필드가 다름 — 상세 패널은 **없는 필드를 `undefined` 로 표기하지 말 것**

## 6. 주요 요구사항 상세

### 6.1 FR-04 · FR-05 · 조회 제어

- 검색어 · 상태 필터 · 부서 필터는 **모두 AND 로 결합**
- 결과 건수는 **필터 적용 후 / 전체** 두 값을 함께 표기
- 필터 초기화는 검색어를 포함한 **모든 조회 조건**을 되돌릴 것
- 0건일 때 빈 표를 그대로 두지 말고 **「조건에 맞는 차량이 없습니다」** 안내를 표시

### 6.2 FR-07 · KPI 카드

| 카드 | 정의 |
| --- | --- |
| 총 대수 | **필터 적용 후** 차량 수 |
| 운행중 대수 | 필터 결과 중 `status == "DRIVING"` |
| EV 평균 SOC | 필터 결과 중 `powertrain == "EV"` 차량의 `soc_pct` 평균, 소수 1자리 |
| 미확인 알람 차량 수 | 필터 결과 중 **`UNACK` 알람을 1건 이상 보유한 차량 수** (차량 기준 중복 제거) |

- 대상이 0대인 카드는 `0` 또는 `—` 로 표기 (`NaN` 금지)

### 6.3 FR-08 · 기준시각 · 데이터 상태

| 상태 | 요구 |
| --- | --- |
| 정상 | 헤더에 `데이터 기준 : 2026-03-17 09:00` 형태로 `as_of` 표기 |
| 로딩 | 로딩 중임을 알 수 있는 표시 (스켈레톤 · 스피너 · 텍스트 무관) |
| 실패 | 파일 로드 실패 시 **오류 메시지 표시** — 빈 화면·무한 로딩 금지 |

### 6.4 FR-11 · 부서 현황

| 컬럼 | 정의 |
| --- | --- |
| 차량 수 | 해당 부서 소속 차량 총 대수 |
| 가동률 | `DRIVING 대수 ÷ 부서 총 대수 × 100`, 소수 1자리 |
| EV 평균 SOC | 해당 부서 **`powertrain == "EV"` 차량만**의 `soc_pct` 평균, 소수 1자리 |
| 알람 차량 수 | 해당 부서에서 알람 1건 이상 보유 차량 수 (**차량 기준 중복 제거**) |

- 가동률 **분모는 부서 전체 대수** (운행중 아닌 차량 포함)
- EV 가 1대도 없는 부서는 `0` 이 아니라 **`—` 로 표기**
- 대시보드의 검색·필터는 **부서 현황에 적용하지 않음** (전체 차량 기준 집계)

### 6.5 FR-12 · 알람 센터 · 확인(ACK)

- 목록 단위는 **알람 건** — 한 차량이 2건이면 2행
- 각 건은 `UNACK`(미확인) / `ACK`(확인) 상태를 가지며, 초기값은 전부 **`UNACK`**
- **FR-07 의 미확인 알람 차량 수는 `UNACK` 알람을 1건 이상 가진 차량 수** — 모든 알람을 ACK 한 차량은 카운트에서 제외
- 기준시각 컬럼은 해당 차량의 `last_seen` 값을 사용

### 6.6 FR-13 · CSV 내보내기

| 항목 | 요구 |
| --- | --- |
| 대상 | **화면에 보이는 그대로** — 필터·정렬 적용 후의 행 순서 |
| 컬럼 | FR-01 목록 컬럼 + 대표 심각도 |
| 인코딩 | 한글이 Excel 에서 깨지지 않을 것 (UTF-8 BOM 등) |
| 값 | 쉼표·따옴표가 포함된 값은 이스케이프 처리 |

### 6.7 FR-14 · 정비 큐

| 동작 | 요구 |
| --- | --- |
| 추가 | 차량 목록·상세 패널·알람 센터 어디서든 큐에 담을 수 있을 것 |
| 항목 | 차량번호 · 담당부서 · 대표 알람 · 예상 입고일(날짜 입력) · 메모(자유 텍스트) |
| 제거 | 큐에서 개별 제거 가능 |
| 배지 | 정비 큐 탭에 현재 건수 표시 |
| 중복 | 같은 차량 중복 등록 불가 |

### 6.8 FR-15 · 전비·연비

| 파워트레인 | 표시 |
| --- | --- |
| `EV` | 전비만 = `Σ distance_km ÷ Σ energy_kwh` |
| `ICE` | 연비만 = `Σ distance_km ÷ Σ fuel_l` |
| `HEV` | **전비·연비 둘 다** (두 필드가 모두 존재함) |

- 해당 필드가 없는 주행 건은 **분모·분자 양쪽에서 제외**
- 분모가 0 이면 `—` 표기 (`Infinity` · `NaN` 금지)

## 7. 알람 판정 규칙 핵심

| ID | 규칙 | 조건 | 심각도 |
| --- | --- | --- | --- |
| **AL-01** | 배터리 부족 | `powertrain == "EV"` **AND** `soc_pct < 15` | 🔴 CRITICAL |
| **AL-02** | 정비 필요 | `status == "MAINTENANCE"` **OR** `dtc_codes` 가 1건 이상 | 🟡 WARNING |
| **AL-03** | 통신 두절 | `as_of - last_seen > 30분` | 🔴 CRITICAL |

### 판정 시 유의사항

- **경계값은 미포함** — `soc_pct == 15.0` 은 AL-01 아님, 무신호 `정확히 30분` 은 AL-03 아님
- **`soc_pct` 가 `null` 인 ICE 차량은 AL-01 대상 아님** (연료량으로 대체 판정하지 않음)
- 한 차량이 **복수 알람**을 가질 수 있음
- **KPI 의 알람 차량 수는 차량 기준 중복 제거**, FR-12 알람 센터는 **알람 건 단위**로 집계
- 차량의 **대표 심각도** = 보유 알람 중 가장 높은 등급 (CRITICAL > WARNING)
