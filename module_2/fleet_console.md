# 커넥티드카 관제 콘솔 — 구현 가이드

## 상황
사내 업무차량 30대가 부서별로 흩어져 운영 중이고, 지금은 부서별 엑셀로 상태를 관리하고 있습니다. 배터리 방전, 통신 두절, 정비 누락이 뒤늦게 발견되는 문제가 반복되고 있습니다.

## 만들 것
전 차량의 상태를 **한 화면**에서 확인하고, **조치가 필요한 차량**을 바로 찾아낼 수 있는 관제 웹 콘솔.

## 제공 데이터
- `vehicles.json` — 차량 30대의 현재 스냅샷 (기준 시각 포함)
- `trips.json` — 차량별 최근 주행 이력

## 꼭 필요한 기능
- **차량 목록**: 상태, 배터리(또는 연료), 주행거리, 담당부서 등을 한눈에 볼 수 있도록 구성
- **검색 / 필터**: 차량번호·차종·부서 등으로 좁혀볼 수 있게
- **요약 KPI**: 전체 대수, 운행중 대수, 알람 차량 수 등을 상단에 요약
- **상세 정보**: 차량 선택 시 상세 정보 + 최근 주행 이력 표시
- **조치 필요 표시**: 아래와 같은 상황의 차량을 알아볼 수 있게 배지/알람으로 표시
  - 배터리가 위험 수준으로 낮은 경우
  - 정비가 필요한 상태이거나 이상 코드가 있는 경우
  - 최근 통신이 오래 끊긴 경우
  - 기준값(몇 % 미만, 몇 분 이상인지)과 경계값 처리는 직접 정하고, 어떻게 정했는지 README에 한 줄로 남겨두세요.
- **정렬**: 원하는 기준으로 목록을 정렬할 수 있게

## 시간이 남으면 도전
- 값이 주기적으로 갱신되는 실시간 시뮬레이션
- 새 알람 발생 시 알림(토스트) + 발생 이력 누적
- 화면 크기에 따라 레이아웃이 바뀌는 반응형 대응

## 자유롭게 정하는 부분
컬럼 구성, 색상/레이아웃, 알람 기준값의 정확한 숫자, 경계값 처리 방식, "알람 차량 수"를 어떻게 집계할지(차량 기준 vs 알람 건 기준) 등은 이 가이드에 명시하지 않았습니다. 데이터를 살펴보고 합리적으로 설계한 뒤, 왜 그렇게 정했는지 간단히 설명할 수 있으면 됩니다.
