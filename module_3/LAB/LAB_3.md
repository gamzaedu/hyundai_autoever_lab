## ✍️ LAB_3-3 — 위반을 규칙으로 (10분)

### 변환 실습 (칠판/화면 공유)

| 🕳️ LAB_3-1 에서 나온 위반 | ✅ 규칙 문장 |
| --- | --- |
| 임계값이 3곳에 산재 | "알람 임계값은 `src/config/thresholds.ts` 에만 정의한다" |

| 임의 리팩터 | "요청 범위 밖 파일은 수정하지 않는다" |
| 검증 생략 | "변경 후 `npm run build` 통과를 확인한 뒤 보고한다" |

### ⚠️ 좋은 규칙 vs 나쁜 규칙

| ❌ 나쁜 규칙 | 왜 나쁜가 | ✅ 좋은 규칙 |
| --- | --- | --- |
| "깔끔하게 작성" | 판정 불가 | "함수는 40줄을 넘기지 않는다" |
| "적절히 상수화" | 기준 없음 | "임계값은 `config/thresholds.ts` 한 곳에만 둔다" |
| "최신 라이브러리 사용" | 방향 반대 | "CDN 링크 금지, 의존성은 `package.json` 에만 추가" |
| "가능하면 테스트" | 강제력 없음 | "변경 후 `npm run build` 를 실행한다" |

> 🔑 **검증 가능한 문장인가?** — 이 질문 하나로 규칙 품질이 갈림
