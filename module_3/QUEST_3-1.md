
## ✅ 검증 — CR-01 기준

| 확인 항목 | 기대 결과 | ☑️ |
| --- | --- | --- |
| 알람 차량 KPI | 10대 → **12대** | ☐ |
| `VH-0013` (SOC 15.0%) | AL-01 알람 **발생** | ☐ |
| `VH-0018` (무신호 30분) | AL-03 알람 **발생** | ☐ |
| 목록 강조 ↔ 알람 배지 | **같은 차량**에 붙음 | ☐ |
| 임계값 정의 위치 | 각각 **1곳**에만 존재 | ☐ |
| 빌드 | `npm run build` 통과 | ☐ |

### 🔎 임계값 산재 확인 명령

```bash
grep -rn "20\|15" src --include=*.ts --include=*.tsx | grep -v config
```

- 👉 판정 기준값이 `config` 밖에서 나오면 **아직 흩어져 있는 것**

## 🚫 자주 하는 실수

| 실수 | 왜 문제인가 |
| --- | --- |
| 프롬프트를 더 자세히 씀 | 규칙 효과인지 프롬프트 효과인지 구분 불가 |
| 규칙을 20개 이상 나열 | 길수록 지켜지지 않음 — **10개 내외**로 |

| 프로젝트 개요를 안 씀 | 도메인 용어(SOC·DTC·텔레메트리)를 모르면 엉뚱한 판단 |
