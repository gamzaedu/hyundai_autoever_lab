## 1️⃣ 스킬 완성 — 채워야 할 4곳

| 위치 | 채울 내용 | 💀 실패 신호 |
| --- | --- | --- |
| `description` | **무엇을 한다 + 언제 쓰는지(트리거 단어 3~5개)** | "PRD 를 만듭니다" → 호출 안 됨 |
| 실행 절차 | 호출 후 작업 **순서** | 지식만 적고 순서가 없음 |
| 출력 형식 | PRD **목차 고정** | "적절한 형식으로" → 매번 다른 결과 |
| 규칙 | **하지 말 것** | 모호어("깔끔하게") 사용 |

### 📏 description 공식

```
<무엇을 한다>. <트리거 단어들>이(가) 나올 때 사용한다.
```

**예시**
```
신규 서비스 기획 요청을 PRD 문서로 작성한다.
"PRD", "기획서", "요구사항 정리", "브리프를 문서로" 같은 요청이 있을 때 사용한다.
```

## 4️⃣ 개정 — ⚠️ 전부 수용하지 마라

`grill-me` 는 **범위를 계속 넓히는 방향**으로 지적한다.
전부 수용하면 "다음 달까지" 라는 브리프의 제약을 위반하는 PRD 가 된다.

| 판단 | 기준 |
| --- | --- |
| ✅ 수용 | 지적을 방치하면 **개발 중 반드시 되물어야 하는** 항목 |
| ❌ 거부 | 1차 범위 밖이거나, 브리프의 제약(무료·API 연동 불가·기한)과 충돌 |

**거부한 건은 PRD 의 `범위 밖(Out of Scope)` 섹션에 사유와 함께 남긴다.**
