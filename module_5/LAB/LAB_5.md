## 🏁 LAB_5-1 「레포 탐색 대결」 (10분)

### 🎬 진행

| 단계 | 행동 |
| --- | --- |
| 0️⃣ | `/clear` → `/context` 로 **시작 잔량 기록** |
| 1️⃣ | **ⓐ 단일 세션** : 직접 레포를 읽어 파악 |
| 2️⃣ | `/context` 로 **잔량 재측정** |
| 3️⃣ | `/clear` → **ⓑ 병렬 3** : 서브에이전트 3개에 영역 분담 |
| 4️⃣ | `/context` 로 **잔량 재측정** → 두 값을 나란히 비교 |

### 🗣️ 투입 프롬프트

**ⓐ 단일 세션**
```
module_3/fleet-console-base 레포 전체를 읽고 구조를 파악해줘.
데이터 흐름, 컴포넌트 관계, 알람 판정 로직을 정리해줘.
```

**ⓑ 병렬 3**
```
module_3/fleet-console-base 를 서브에이전트 3개로 나눠서 병렬로 파악해줘.
- 1번: src/lib (알람 판정, 포맷 유틸)
- 2번: src/components (UI 구조와 props 흐름)
- 3번: public/data (데이터 스키마와 필드 의미)
각자 요약만 돌려받고, 네가 최종 통합해줘.
```

### 📊 기록표 (칠판/화면에 그대로 적기)

| 지표 | ⓐ 단일 | ⓑ 병렬 3 | 관찰 |
| --- | --- | --- | --- |
| `/context` 잔여 % | | | |
| 소요 시간 | | | |
| 요약 정확도 (틀린 서술 수) | | | |

### 💡 예상 결과와 해석

| 관찰 | 해석 |
| --- | --- |
| ⓑ 의 **잔량이 크게 남음** | 파일 원문은 **서브에이전트 컨텍스트**에서 타고, 나에게는 요약만 온다 |
| ⓑ 가 **더 빠르지는 않을 수 있음** | 병렬의 이득은 **속도가 아니라 컨텍스트** |
| ⓑ 요약이 **더 얕을 수 있음** | 요약 과정에서 정보 손실 발생 → 트레이드오프 |

> ⚠️ **정직하게 짚을 것** : 병렬이 항상 낫지 않다. 파일 3개짜리 작업에 서브에이전트를 쓰면 **오히려 손해**다.
> 판단 기준은 "원문을 내 컨텍스트에 **남길 필요가 있는가**" 다.

## 🎭 LAB_5-2 「역할 부여」 (10분)

### 🎬 진행

| 단계 | 행동 | 보여줄 것 |
| --- | --- | --- |
| 1️⃣ | `security-reviewer.md` 를 화면에 열어 구조 설명 | frontmatter(`name`·`description`·`tools`) + 시스템 프롬프트 |
| 2️⃣ | **"점검 범위 밖"** 섹션을 강조 | 시야를 **좁히는 것**이 핵심 |
| 3️⃣ | 3종 에이전트를 병렬 호출 | 같은 코드, **다른 눈** |
| 4️⃣ | 3개 리포트를 나란히 비교 | 겹치는 지적이 거의 없음 |

### 🗣️ 투입 프롬프트

```
module_5/exercise/exercise_5-1/review-target 를
security-reviewer, performance-reviewer, convention-reviewer 3개로 병렬 리뷰해줘.
각 리포트를 그대로 보여주고, 마지막에 통합 표 1개만 만들어줘.
```

### 💡 강조 포인트

| 포인트 | 멘트 |
| --- | --- |
| ✂️ 시야 제한 | "**보지 말 것**을 적는 게 볼 것을 적는 것보다 중요하다" |
| 🔧 도구 제한 | "리뷰어에게 `Write` 를 주지 않는다. **읽기만** 시킨다" |
| 📐 출력 고정 | "표 형식을 고정해야 3개 리포트를 **합칠 수 있다**" |
| 🎯 description | "4교시와 동일 — description 이 곧 **호출 트리거**" |

## ⚖️ LAB_5-3 「실패 사례」 (LAB_5-2 내 3분)

### 🎬 진행

일부러 **같은 파일을 3개 에이전트가 동시에 수정**하게 시킨다.

### 🗣️ 투입 프롬프트

```
서브에이전트 3개를 병렬로 띄워서 VehicleTable.tsx 를 각각 개선해줘.
1번은 보안, 2번은 성능, 3번은 컨벤션 관점으로 직접 수정해.
```

### 💥 예상 파국

| 증상 | 원인 |
| --- | --- |
| 🔀 마지막 에이전트 결과만 남음 | 동일 파일 덮어쓰기 |
| 🧩 세 수정이 뒤엉켜 빌드 실패 | 서로의 변경을 모름 |
| 🔁 같은 일을 3번 함 | 역할 경계 미설정 |

### 📏 원칙표

| 작업 | 병렬 | 사유 |
| --- | --- | --- |
| 📖 읽기 · 탐색 · 리뷰 | ✅ 적극 사용 | 충돌 없음, 컨텍스트 절약 |
| ✍️ 같은 파일 수정 | ❌ 금지 | 덮어쓰기 충돌 |
| ✍️ 다른 파일 수정 | ⚠️ 조건부 | 경계가 명확할 때만 |
| 🧠 합의·판단 | ❌ 금지 | 최종 판단은 **본 세션**이 한다 |

> 💥 **결정타 멘트**
> "서브에이전트는 **조사원**이지 **결재자**가 아니다.
> 조사는 나눠서 시키고, **결정은 한 명이** 한다."
