# M1. 업무차량 정비 이력 관리

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v1.0 |
| 기준 시각 | `2026-03-17T09:00:00+09:00` |
| 난이도 | 중 |

---

## 1. 배경

업무차량 30대의 정비 이력은 정비소별 영수증과 담당자 개인 스프레드시트로 분산 관리되고 있다. 다음 정비 시점은 담당자가 수기로 계산하며, 주행거리 기준 항목과 기간 기준 항목이 섞여 있어 누락이 발생한다.

정비 이력을 조회하고 다음 정비 시점을 자동 산출하는 화면을 구축한다.

## 2. 사용자

| 구분 | 사용 목적 |
| --- | --- |
| 차량 관리 담당 | 차량별 이력 조회, 정비 지연 차량 파악 |
| 관제 담당 | DTC 발생 차량의 최근 정비 이력 확인 |
| 예산 담당 | 정비 비용 집계 |

## 3. 기능 요구사항

| ID | 구분 | 요구사항 | 상세 |
| --- | --- | --- | --- |
| FR-01 | 필수 | 차량 목록 | 30대 표시. 차량번호 · 차종 · 파워트레인 · 현재 주행거리 · 최근 정비일 노출 |
| FR-02 | 필수 | 차량별 이력 | 차량 선택 시 해당 차량의 정비 이력을 최근순으로 표시 |
| FR-03 | 필수 | **정비 지연 판정** | §3.1 규칙으로 지연 여부를 판정하고 목록에서 강조 |
| FR-04 | 필수 | 이력 등록 | 신규 정비 이력 등록 (항목 · 유형 · 일시 · 주행거리 · 비용 · 정비소) |
| FR-05 | 필수 | 요약 지표 | 총 차량 수 · 정비 지연 차량 수 · 이번 달 정비 건수 · 총 정비 비용 |
| FR-06 | 필수 | 유형 필터 | `REGULAR` · `REPAIR` · `RECALL` 다중 선택 |
| FR-07 | 선택 | 이력 수정 | 등록된 이력의 비용 · 정비소 수정 |
| FR-08 | 선택 | 다음 정비 예측 | 최근 이력 기준 다음 정비 시점을 주행거리·기간 양쪽으로 산출해 표시 |
| FR-09 | 선택 | 비용 집계 | 차량별 · 항목별 누적 비용 표시 |

### 3.1 정비 지연 판정 규칙

| ID | 규칙 |
| --- | --- |
| BR-01 | 주행거리 기준 : `next_due_km` 가 있고 차량의 현재 `odometer_km` 가 `next_due_km` **이상**이면 지연. |
| BR-02 | 기간 기준 : `next_due_at` 이 있고 `as_of` 가 `next_due_at` **이후**이면 지연. |
| BR-03 | 두 기준 중 **하나라도** 충족하면 해당 이력은 지연이다. |
| BR-04 | `next_due_km` 와 `next_due_at` 이 **모두 null** 인 이력은 판정 대상이 아니다. (일회성 수리 · 리콜) |
| BR-05 | 차량 단위 지연 여부 = 그 차량의 이력 중 지연이 1건 이상 존재. |
| BR-06 | 임박 = 주행거리 기준 잔여 **1,000km 이내** 또는 기간 기준 잔여 **14일 이내**. 지연과 구분해 표시한다. |

### 3.2 계산 규칙

| 규칙 | 내용 |
| --- | --- |
| R-01 | 모든 기간 계산의 기준은 `as_of` 이다. 시스템 현재 시각을 사용하지 않는다. |
| R-02 | `cost_krw` 가 `null` 인 이력(보증 수리 · 리콜)은 비용 합계에서 **제외**한다. `0` 으로 치환하지 않는다. |
| R-03 | 유형 라벨은 `types[].label` 의 한글 값을 사용한다. |
| R-04 | 지연·임박 임계값은 단일 지점에 정의한다. |
| R-05 | "이번 달"은 `as_of` 가 속한 월(2026-03)이다. |

## 4. 데이터 명세

### 4.1 파일

| 파일 | 건수 | 설명 |
| --- | --- | --- |
| `data/maintenance_logs.json` | 90 | 정비 이력 |
| `data/vehicles.json` | 30 | 차량 마스터 |
| `data/trips.json` | 30대 × 5건 | 최근 주행 이력 (선택 활용) |

### 4.2 `logs[]` 필드

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `log_id` | string | 이력 ID (`MT-0001` 형식) |
| `vehicle_id` | string | `vehicles[].vehicle_id` 참조 |
| `plate` | string | 차량 번호 |
| `type` | enum | `REGULAR` \| `REPAIR` \| `RECALL` |
| `item` | string | 정비 항목 |
| `performed_at` | string | 정비 일시 (ISO 8601) |
| `odometer_km` | number | 정비 당시 주행거리 |
| `cost_krw` | number \| null | 비용. 보증·리콜은 `null` |
| `warranty` | boolean | 보증 적용 여부 |
| `shop` | string | 정비소 |
| `next_due_km` | number \| null | 다음 정비 주행거리 |
| `next_due_at` | string \| null | 다음 정비 기한 |
| `dtc_codes` | string[] | 연관 진단코드. 빈 배열 가능 |
| `note` | string \| null | 비고 |

### 4.3 `vehicles[]` 주요 필드

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `vehicle_id` | string | 차량 ID (`VH-0001` 형식) |
| `plate` | string | 차량 번호 |
| `model` | string | 차종 |
| `powertrain` | enum | `EV` \| `HEV` \| `ICE` |
| `odometer_km` | number | 현재 주행거리 |
| `dtc_codes` | string[] | 현재 진단코드 |

### 4.4 분포 및 결측 현황

| 항목 | 건수 |
| --- | --- |
| `REGULAR` | 50 |
| `REPAIR` | 32 |
| `RECALL` | 8 |
| `cost_krw` = null | 17 |
| `next_due_km` = null | 39 |
| `next_due_at` = null | 47 |
| `dtc_codes` 보유 이력 | 4 |
| 이력이 존재하는 차량 | 28 / 30 |
| 판정 대상 아님 (`next_due_*` 모두 null) | 19 |

**BR-01~BR-05 적용 시 기대값** — 지연 이력 **22건**, 지연 차량 **17대**

> 이력이 없는 차량 2대는 정상 상태다. "이력 없음"을 화면에서 오류로 처리하지 않는다.

### 4.5 참조 무결성

- `logs[].vehicle_id` 는 모두 `vehicles[].vehicle_id` 에 존재한다.
- `performed_at` 은 모두 `as_of` 이전이다.
- `odometer_km` 은 해당 차량의 현재 `odometer_km` 이하이다.
