# M1. 사내 EV 충전기 예약 서비스

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v1.0 |
| 기준 시각 | `2026-03-17T09:00:00+09:00` |

---

## 1. 배경

본사 지하 2층 충전존은 선착순으로 운영되어 오후 출근 직원은 충전기를 사용하지 못하는 경우가 많다. 완충 후에도 차량을 이동시키지 않아 자리가 장시간 점유되는 문제가 반복 제기되었다.

시간대 예약제로 전환하기 위한 예약 서비스를 구축한다.

## 2. 사용자

| 구분 | 사용 목적 |
| --- | --- |
| 전기차 이용 직원 | 충전기 예약 · 확인 · 취소 |
| 총무팀 | 예약 현황 파악, 노쇼 발생 확인 |

## 3. 기능 요구사항

| ID | 구분 | 요구사항 | 상세 |
| --- | --- | --- | --- |
| FR-01 | 필수 | 예약 현황 타임라인 | 충전기 8기 × 시간대 격자. 예약 구간을 상태별로 표시 |
| FR-02 | 필수 | 예약 생성 | 충전기 · 시작시각 · 이용시간 선택 후 예약 등록 |
| FR-03 | 필수 | **중복 예약 차단** | 동일 충전기의 시간대가 겹치는 예약 생성을 거부하고 사유를 표시 |
| FR-04 | 필수 | 예약 취소 | `BOOKED` 상태 예약 취소. 취소 사유 입력 |
| FR-05 | 필수 | 내 예약 조회 | 직원 선택 시 해당 직원의 예약만 표시 |
| FR-06 | 필수 | 요약 지표 | 오늘 예약 건수 · 진행중 · 노쇼 건수 · 가용 충전기 수 |
| FR-07 | 선택 | 노쇼 판정 표시 | 노쇼 예약을 목록에서 구분 표시하고 사유 안내 |
| FR-08 | 선택 | 1인 예약 상한 | 1인당 당일 예약 2건 초과 시 생성 거부 |
| FR-09 | 선택 | 가용 슬롯 추천 | 원하는 시간대에 예약 가능한 충전기를 제안 |

### 3.1 예약 규칙

| ID | 규칙 |
| --- | --- |
| BR-01 | 예약 단위는 **30분**이다. 시작 시각은 정시 또는 30분이어야 한다. |
| BR-02 | 1회 예약 길이는 **최소 30분, 최대 120분**이다. |
| BR-03 | 동일 충전기에서 시간대가 겹치는 활성 예약(`BOOKED` · `IN_USE` · `DONE` · `NOSHOW`)은 존재할 수 없다. 경계가 맞닿는 경우(앞 예약 종료 = 뒤 예약 시작)는 겹침이 아니다. |
| BR-04 | `FAULT` · `MAINTENANCE` 상태 충전기는 예약할 수 없다. |
| BR-05 | 과거 시각(`as_of` 이전 시작)으로는 신규 예약을 생성할 수 없다. |
| BR-06 | 노쇼 = 예약 시작 후 **15분** 경과까지 `checked_in_at` 이 없는 경우. |
| BR-07 | 취소는 `BOOKED` 상태에서만 가능하다. |

### 3.2 상태 정의

| status | 한글 라벨 | 설명 |
| --- | --- | --- |
| `BOOKED` | 예약됨 | 시작 전 |
| `IN_USE` | 이용중 | 체크인 완료, 종료 전 |
| `DONE` | 완료 | 이용 종료 |
| `NOSHOW` | 노쇼 | 체크인 없이 시작 시각 경과 |
| `CANCELED` | 취소 | 이용자 취소 |

### 3.3 계산 규칙

| 규칙 | 내용 |
| --- | --- |
| R-01 | "지금", "오늘"의 기준은 `as_of` 이다. 시스템 현재 시각을 사용하지 않는다. |
| R-02 | 예약 길이 · 노쇼 유예 시간 등 임계값은 단일 지점에 정의한다. |
| R-03 | 화면에 노출하는 상태 문자열은 §3.2 의 한글 라벨을 사용한다. |
| R-04 | `CANCELED` 예약은 충돌 검사 대상에서 제외한다. |

## 4. 데이터 명세

### 4.1 파일

| 파일 | 건수 | 설명 |
| --- | --- | --- |
| `data/chargers.json` | 8 | 충전기 마스터 + 충전존 정보 |
| `data/reservations.json` | 24 | 예약 이력 + 직원 16명 |

### 4.2 `reservations[]` 필드

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `reservation_id` | string | 예약 ID (`R-001` 형식) |
| `charger_id` | string | `chargers[].charger_id` 참조 |
| `employee_id` | string | `employees[].employee_id` 참조 |
| `plate` | string | 차량 번호 |
| `dept` | string | 부서 |
| `start_at` | string | 시작 일시 (ISO 8601) |
| `end_at` | string | 종료 일시 |
| `status` | enum | §3.2 참조 |
| `created_at` | string | 예약 생성 일시 |
| `checked_in_at` | string \| null | 체크인 일시. 미체크인 시 `null` |
| `cancel_reason` | string \| null | 취소 사유 |

### 4.3 `employees[]` 필드

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `employee_id` | string | 사번 (`E-1007` 형식) |
| `name` | string | 성명 |
| `dept` | string | 부서 |
| `plate` | string | 등록 차량 번호 |

### 4.4 상태 분포

| status | 건수 |
| --- | --- |
| `BOOKED` | 9 |
| `IN_USE` | 4 |
| `DONE` | 6 |
| `NOSHOW` | 3 |
| `CANCELED` | 2 |

### 4.5 참조 무결성

- `charger_id` · `employee_id` 는 모두 마스터에 존재한다.
- 활성 예약의 시간대 중첩은 **0건**이다. (초기 데이터는 BR-03 을 만족한다)
- `FAULT` · `MAINTENANCE` 충전기(CH-04 · CH-08)에는 예약이 존재하지 않는다.
- `IN_USE` 충전기(CH-01 · CH-03 · CH-05 · CH-07)의 `current_reservation_id` 는 `IN_USE` 예약을 가리킨다.
- 상태별 시간 정합성은 초기 데이터에서 모두 성립한다. (`DONE` 종료 ≤ `as_of` < `IN_USE` 종료, `BOOKED` 시작 > `as_of`)

## 5. 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-01 | CDN 링크 사용 금지. 모든 자산은 로컬 번들. |
| NFR-02 | 외부 API 호출 금지. 충전기 제조사 API 연동 불가(망 정책). |
| NFR-03 | `README.md` 에 기재된 명령 1회로 로컬 기동. |
| NFR-04 | 예약 생성·취소는 메모리 또는 브라우저 로컬 저장소에 유지한다. 서버 구축은 선택 사항. |
| NFR-05 | 예약 규칙(BR-01~BR-07)은 코드 내 단일 지점에 상수 또는 설정으로 정의한다. |
